# 인터뷰 설계 기준

## 먼저 정할 것

- 인터뷰가 끝나면 바꿀 판단이나 채울 근거가 무엇인지 한 문장으로 쓴다.
- 참여자가 직접 경험한 범위와 답할 수 없는 범위를 구분한다.
- 이미 공개 문서로 확인되는 사실과 현장에서만 확인할 수 있는 실제 흐름을 나눈다.
- 참여자 수가 적으면 대표성보다 사례의 과정과 반례 확인을 목표로 둔다.

## 연락·동의 경계

연락문과 진행안에는 목적, 예상 방식과 시간, 자발적 참여, 기록·녹음 여부, 인용·익명 처리, 보관과 2차 사용 범위를 분명히 적는다. 연락 발송, 참여 동의와 녹음 시작은 사용자가 직접 확인한다.

법적 동의서나 기관 연구윤리 심의가 필요한지는 이 스킬이 판정하지 않는다. 소속기관 규정과 담당자의 안내를 별도로 확인한다. 사용자를 대신해 연락처, 경험, 소속 합의나 동의 여부를 만들어 넣지 않는다.

## 질문 흐름

1. 참여자의 역할과 답변 범위를 확인한다.
2. 최근의 구체적 사례를 시간순으로 묻는다.
3. 공식 절차와 실제 수행이 달라지는 지점을 묻는다.
4. 잘 이어진 사례와 멈춘 사례를 같은 단계로 비교한다.
5. 예외, 실패, 반대 사례와 알 수 없는 부분을 묻는다.
6. 후속 확인이 필요한 자료와 담당 범위를 확인한다.

한 질문에 두 판단을 묶지 않는다. `문제가 심각하지요?`처럼 결론을 넣지 않고 `최근 한 사례에서 어느 단계가 어떻게 진행됐습니까?`처럼 행동과 흐름을 묻는다. 참여자가 쓰지 않은 전문용어로 답을 재구성하지 않는다.

## 민감정보 최소화

- 이름 대신 역할이나 익명 ID를 사용한다.
- 환자·이용자·사례 대상자를 알아볼 수 있는 날짜, 지역, 희귀 특성의 조합도 줄인다.
- 내부 명단, 원본 상담·진료기록, 시스템 화면과 계정정보는 받지 않는다.
- 구체적 사례는 절차를 이해하는 데 필요한 수준만 기록한다.
- 녹취와 메모의 보관 위치·접근 범위·삭제 시점을 인터뷰 전에 정한다.

## 진행 전 확인

- 질문마다 어떤 주장이나 빈칸을 확인하는지 연결되어 있는가
- 공개자료로 답할 질문을 참여자에게 반복하지 않는가
- 성공 사례와 중단 사례를 모두 물을 수 있는가
- 유도질문, 평가 요구, 책임 추궁처럼 들리는 표현이 없는가
- 답하지 않을 권리와 녹음·인용 범위가 분명한가
- 실제 연락과 녹음에 사용자 승인이 있는가
