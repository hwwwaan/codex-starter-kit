# 현장 인터뷰를 근거로 전환

인터뷰 답변을 일반 사실처럼 확대하지 않는다. 누가 어떤 위치에서 무엇을 경험하거나 보았는지 범위를 보존해 판단 가능한 근거로 만든다.

## 어떤 자료를 읽을까

- 질문지·섭외문·진행안 준비나 검토라면 [인터뷰 설계 기준](references/interview-protocol.md)을 읽는다.
- 녹취·메모·답변을 주장과 근거로 바꾸는 작업이라면 [근거화 기준](references/evidence-conversion.md)을 읽는다.
- 새 기록지가 필요하면 [현장 인터뷰 기록지](assets/interview-record-template.md)를 복사해 목적에 맞게 줄인다.

## 준비

1. 인터뷰 뒤 바꿀 판단, 확인할 주장과 참여자가 답할 수 있는 범위를 먼저 정한다.
2. 기존 문헌·정책·내부 자료로 확인되는 사실은 다시 묻지 않고, 문서와 실제 이행 사이의 빈칸을 질문한다.
3. 한 질문에 쟁점을 하나만 두고, 평가를 유도하는 표현보다 최근의 구체적 흐름과 반례를 묻는다.
4. 잘 이어진 사례와 멈춘 사례를 같은 단계로 복원할 수 있게 질문 순서를 맞춘다.
5. 개인정보·환자기록·상담기록·내부 명단·시스템 화면을 요구하지 않는다.

외부 연락, 참여 동의, 녹음 시작과 자료의 2차 사용은 사용자가 직접 확인하고 실행한다. 승인되지 않은 연락이나 녹음을 대신 수행하지 않는다.

## 근거화

- 직접 인용은 실제 녹취나 정확한 기록이 있을 때만 쓰고, 요약은 `요약`이라고 표시한다.
- 답변을 `구체적 사례 / 반복되는 실무 / 공식 원칙 / 참여자 해석 / 추정 / 미확인`으로 나눈다.
- 제도상 절차와 실제 수행, 최근 한 사례와 일반 관행, 직접 경험과 전해 들은 내용을 구분한다.
- 한 사람의 경험으로 빈도·대표성·인과관계·기관 전체의 상태를 단정하지 않는다.
- 서로 다른 답변이 충돌하면 합치지 않고 출처 범위와 충돌 지점을 함께 남긴다.
- 무응답, 기억하지 못함, 알지 못함을 `없음`으로 바꾸지 않는다.
- 기존 주장과 맞지 않는 답변을 우선 확인하고, 유지·수정·보류·삭제 판단을 근거와 연결한다.

## 결과

목적에 필요한 것만 골라 다음을 만든다.

1. 인터뷰 목적·참여자 범위·질문지와 진행 유의사항
2. 식별정보를 제외한 답변 기록과 근거 단위
3. 주장별 지지·반증·충돌·미확인 원장
4. 기존 판단에서 달라진 점과 추가 확인 질문

일반 회의의 결정·담당·기한 정리는 `meeting-to-action`, 문헌과 공식자료 조사는 `evidence-research` 범위다. 인터뷰 자료를 원래 동의 범위 밖의 개인 연구나 외부 서비스로 옮기지 않는다.
