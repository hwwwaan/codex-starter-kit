# 전문 산출물 제작

문장 생성과 파일 제작을 분리한다. 먼저 내용이 맞는지 확정하고, 그다음 형식에 맞는 파일을 만든다.

## 내용 설계

1. 목적, 독자, 사용 상황, 분량, 형식, 마감, 기존 양식을 확인한다.
2. 주장과 필요한 근거를 연결한 뒤 목차 또는 장표 흐름을 만든다.
3. 사용자에게 방향 승인이 필요한 큰 선택이 있으면 최적안과 이유를 먼저 제시한다.
4. 최신 사실과 수치는 원출처로 검증하고, 미확인 항목을 본문에서 단정하지 않는다.
5. [산출물 기준](references/deliverable-standards.md)에서 해당 형식을 읽고 적용한다.

## 파일 제작

- 기존 양식이 있으면 구조, 표, 글꼴, 여백, 필수 항목을 보존한다.
- 원본을 덮어쓰지 않고 새 파일명으로 저장한다.
- DOCX, PPTX, XLSX, PDF 등 형식 전용 기능이나 스킬이 있으면 사용한다.
- 사용자가 바이너리 문서 형식을 요구했는데 해당 형식을 실제 생성·열기·검증할 기능이 없으면 완성했다고 보고하지 않는다. 가능한 내용 초안과 정확한 기능 한계를 분리해 보고한다.
- 외부물에는 프롬프트, 내부 파일 경로, 작업 메모, 미완성 표시, 불필요한 개인정보를 남기지 않는다.
- 사용자가 읽을 최종본은 `03_완성본`에 저장하고 중간 산출물과 분리한다.

## 검증

전체 본문을 처음부터 끝까지 읽어 주장, 용어, 숫자, 중복, 누락을 확인한다. 실제 렌더링 또는 형식 구조검사를 수행해 잘림, 표 손상, 빈 페이지, 글꼴 대체를 검사한다. 렌더링이나 구조검사를 수행하지 못했으면 `시각 검수 미실시`를 명시하며 외부 제출 준비 완료로 판정하지 않는다. 파일 존재만으로 완성이라고 판단하지 않는다.

검토만 요청받은 경우에는 파일을 수정하지 않고 문제, 영향, 수정 권고를 보고한다.
