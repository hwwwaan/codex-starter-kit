# 최종 품질감사

작성자의 설명을 신뢰하지 말고 실제 산출물과 근거를 독립적으로 확인한다.

## 감사 범위

1. 사용자 원요청과 완료 기준을 다시 읽는다.
2. 인도 대상 파일의 전체 내용과 실제 파일 상태를 확인한다.
3. [감사표](references/audit-matrix.md)의 모든 항목을 검사한다.
4. 발견한 문제를 치명도에 따라 차단 결함과 개선사항으로 분리한다.

## 판정

- `PASS`: 필수 범위가 충족되고 외부 사용을 막는 결함이 없음
- `BLOCK`: 누락, 미확인 핵심 주장, 수치 오류, 개인정보 노출, 내부 흔적, 파일 손상, 양식 위반 중 하나라도 있음

BLOCK이면 가능한 범위에서 결함을 직접 수정하고 동일 항목을 다시 검사한다. 수정 권한이 없거나 원자료가 없어 고칠 수 없을 때만 정확한 차단 사유와 필요한 조치를 보고한다.

## 보고

판정, 확인한 파일과 범위, 핵심 검사결과, 수정한 결함, 남은 한계를 간결하게 남긴다. 검사하지 않은 항목을 통과했다고 말하지 않는다.
